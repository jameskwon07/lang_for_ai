# E2 boundary alignment: agreement of morpheme and token boundaries by spelling scheme

This summary was generated by `alignment.py`. Every number was measured by this script, and the raw data is in `alignment.json`.

## 0. Summary

1. **The combination closest to morpheme = token is `W2_spaced` + token_picked.** It passed the strict criterion on 5/7 tokenizers (o200k, cl100k, llama3, llama4, mistral_tekken), with tokens/morpheme 1.01. Tokenizers that did not pass: claude_legacy (1.13, R 1.00, P 0.89); mistral_sp (1.33, R 1.00, P 0.75).
   - Combinations that passed on all 7: none. With the naive inventory, no tokenizer passed even the loose criterion under any spelling.
   - So spelling alone does not make morpheme = token. The forms must be chosen so that their leading-space form is a single token, and morphemes must be separated by spaces (W2) so that the chosen forms stay single tokens in context.
2. **Spaces in W2**: No space-only token appeared in any tokenizer or inventory. With token-picked forms, " kat" is a single token in context at least 95% of the time on 5 tokenizers (o200k, cl100k, llama3, llama4, mistral_tekken), and on these W2 uses 3.0–5.3 **fewer** tokens per message than W1. The space is more than free: it reduces tokens.
   - claude_legacy: single-token share 88%, W2 − W1 = -0.6 tokens/message → not free.
   - mistral_sp: single-token share 67%, W2 − W1 = +2.3 tokens/message → not free.
   - With naive forms the single-token share is 33%–70%, so the space is not free.
3. **Cost of glued writing (W1)**: depending on the inventory, W1 uses more or fewer tokens than W2, but the boundary mismatch is similarly large in every inventory. (Mean over tokenizers)
   - naive: recall 0.79, precision 0.57, single-token morphemes 37% (roots 8%, affixes 68%). Tokens per message W1 43.3 / W2 46.9 (W1 is -8% vs W2), cheapest spelling W1_nospace (43.3).
   - token_picked: recall 0.83, precision 0.71, single-token morphemes 60% (roots 47%, affixes 74%). Tokens per message W1 36.6 / W2 33.8 (W1 is +8% vs W2), cheapest spelling W2_spaced (33.8).
   - bare_picked: recall 0.79, precision 0.72, single-token morphemes 63% (roots 60%, affixes 65%). Tokens per message W1 34.8 / W2 39.7 (W1 is -12% vs W2), cheapest spelling W1_nospace (34.8).
   - In glued writing, BPE splits off the first consonant of a root (`mab`+`ef` → `m|ab|ef`) or groups the last consonant of a root with the following affix (`mul`+`ox` → `mu|lox`, claude_legacy). So roots in particular are often split. Even when forms are chosen by their glued form (bare-picked), recall stays at 0.79.
   - Character counts are W1 79.3 and W2 109.8 characters/message, so spaces add 38% characters, but this is separate from the token count.
4. **Capitalized spellings (W4, W5)**: capitals create token boundaries, so recall is high at 0.97–1.00, but forms that start with a capital are often not a single token (`G|id`), so tokens/morpheme is 1.18–1.95 and precision 0.50–0.84. The added W6 (lowercamel, token-picked) passed only the loose criterion, on o200k (1.06, R 1.00, P 0.94), llama4 (1.08, R 1.00, P 0.92).
5. **The form pool is the bottleneck.** Among CVC forms that pass the word filter (zipf < 3.0), there are 59 token-picked roots (32 of them are single tokens on all 7), far short of the documented target of 500–1,000 roots. Relaxing the filter to zipf < 4.0 gives 261. Only 1 VC affix form passes zipf < 3, so the affix filter was relaxed.

## 1. Setup

- 300 synthetic messages of 20–40 morphemes (mean 31.5), 14.69 words on average, affix share 48%, compound word (2 roots) share 11%.
- A message is a sequence of sentences (predicate word + 1–3 argument words + an occasional modifier word). Root and affix usage frequency is rank^-1 (Zipf).
- All inventories and spellings use **the same skeletons**; only the forms change. For each inventory the lexicon (form assignment) was drawn 5 times and the results pooled.
- Lexicon size: 59 roots, 34 affixes (shared by the three inventories, matched to the smallest pool).
- Boundary rule: a space belongs to the following morpheme. If a space becomes a separate token, precision drops.
- The "leading-space form" for mistral_sp is measured by feeding `kat` (SentencePiece adds `▁` by itself, so this is the same as `▁kat`).

## 7. Limitations

- This experiment only measured whether token boundaries match morphemes. It cannot tell whether a mismatch actually lowers an LLM's reading and writing accuracy (that needs a model experiment such as `pilot_segmentation.py`).
- The current Claude tokenizer is not public, so it cannot be measured. claude_legacy is the Claude 2-era tokenizer and only a proxy.
- token-picked + W2 passing on 5 tokenizers is an expected result, because the condition is almost the same as the selection criterion (leading-space form is a single token). What this experiment adds is (1) that the property holds in context too, and (2) that the tokenizers often left out during selection (claude_legacy, mistral_sp) remain weak points.
- The lexicon is small (59 roots, 34 affixes, matched to the smallest pool). The range across draws is given in the section 2 tables.
- The word filter for affixes was relaxed to zipf < 4.5. In W2, affixes appear as standalone tokens, so they may look like short words of other languages.
- The token-picked pool contains forms such as vec, req and xor that can be read as English abbreviations or code fragments (the list is `token_picked_roots` in the json). The word filter (wordfreq) does not catch such fragments, so resistance to human reading (G2) must be assessed separately.
- Standalone tokenization of glued forms cannot be measured for mistral_sp with toklib, so mistral_sp was left out of the bare-picked selection and the standalone measurements. It is included in the whole-message measurements.

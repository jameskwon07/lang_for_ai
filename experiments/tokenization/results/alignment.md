# E2 경계 정렬: 표기 방식별 형태소·토큰 경계 일치

`alignment.py` 가 만든 요약이다. 숫자는 모두 이 스크립트로 잰 값이며, 원자료는 `alignment.json` 에 있다.

## 0. 요약

1. **형태소 = 토큰에 가장 가까운 조합은 `W2_spaced` + token_picked** 이다. 엄격 기준을 5/7개 토크나이저(o200k, cl100k, llama3, llama4, mistral_tekken)에서 통과했다 (토큰/형태소 1.01). 통과하지 못한 토크나이저: claude_legacy (1.13, R 1.00, P 0.89); mistral_sp (1.33, R 1.00, P 0.75).
   - 7개 모두를 통과한 조합은 없다. naive 인벤토리는 어떤 표기에서도 느슨한 기준조차 통과한 토크나이저가 없다.
   - 즉 표기만으로는 형태소 = 토큰이 되지 않는다. 앞 공백 형태가 1토큰인 형태를 골라야 하고, 형태소마다 띄어 써야(W2) 고른 형태가 문맥 안에서도 그대로 1토큰으로 남는다.
2. **W2 의 공백**: 공백만으로 된 토큰은 어느 토크나이저·인벤토리에서도 하나도 생기지 않았다. token-picked 형태에서는 " kat" 이 문맥 안에서 1토큰인 비율이 95% 이상인 토크나이저가 5개(o200k, cl100k, llama3, llama4, mistral_tekken)이고, 이들에서 W2 는 W1 보다 메시지당 3.0~5.3 토큰 **적다**. 공백이 공짜인 정도를 넘어 오히려 토큰을 줄인다.
   - claude_legacy: 1토큰 비율 88%, W2 − W1 = -0.6 토큰/메시지 → 공짜가 아니다.
   - mistral_sp: 1토큰 비율 67%, W2 − W1 = +2.3 토큰/메시지 → 공짜가 아니다.
   - naive 형태에서는 1토큰 비율이 33%~70% 로 공짜가 아니다.
3. **붙여 쓰기(W1)의 비용**: 토큰 수는 인벤토리에 따라 W2 보다 많기도 적기도 하지만, 경계 어긋남은 어느 인벤토리에서나 비슷하게 크다. (토크나이저 평균)
   - naive: recall 0.79, precision 0.57, 1토큰 형태소 37% (어근 8%, 접사 68%). 메시지당 토큰 W1 43.3 / W2 46.9 (W1 이 W2 보다 -8%), 가장 적은 표기는 W1_nospace (43.3).
   - token_picked: recall 0.83, precision 0.71, 1토큰 형태소 60% (어근 47%, 접사 74%). 메시지당 토큰 W1 36.6 / W2 33.8 (W1 이 W2 보다 +8%), 가장 적은 표기는 W2_spaced (33.8).
   - bare_picked: recall 0.79, precision 0.72, 1토큰 형태소 63% (어근 60%, 접사 65%). 메시지당 토큰 W1 34.8 / W2 39.7 (W1 이 W2 보다 -12%), 가장 적은 표기는 W1_nospace (34.8).
   - 붙여 쓰면 BPE 가 어근 첫 자음을 떼어 내거나(`mab`+`ef` → `m|ab|ef`) 어근 끝 자음을 뒤 접사와 묶는다(`mul`+`ox` → `mu|lox`, claude_legacy). 그래서 어근이 특히 많이 쪼개진다. 붙여 쓴 형태 기준으로 골라도(bare-picked) recall 은 0.79 에 머문다.
   - 글자 수는 W1 79.3, W2 109.8 글자/메시지로 공백이 글자를 38% 늘리지만, 토큰 수와는 별개다.
4. **대문자 표기(W4, W5)**: 대문자가 토큰 경계를 만들어 recall 은 0.97~1.00 로 높지만, 대문자로 시작하는 형태는 1토큰이 아닌 경우가 많아(`G|id`) 토큰/형태소 1.18~1.95, precision 0.50~0.84 이다. 추가한 W6(lowercamel, token-picked)은 느슨한 기준만 o200k (1.06, R 1.00, P 0.94), llama4 (1.08, R 1.00, P 0.92) 에서 통과했다.
5. **형태 풀이 병목이다.** 단어 필터(zipf < 3.0)를 통과한 CVC 중 token-picked 어근은 59개(7개 모두에서 1토큰은 32개)로, 문서의 목표 어근 수 500~1,000개에 크게 못 미친다. 필터를 zipf < 4.0 으로 풀면 261개다. VC 접사는 zipf < 3 을 통과하는 형태가 1개뿐이라 접사 필터를 완화했다.

## 1. 설정

- 합성 메시지 300개, 형태소 20~40개 (평균 31.5), 단어 평균 14.69개, 접사 비율 48%, 합성어(어근 2개) 비율 11%.
- 메시지 = 문장(술어 단어 + 논항 단어 1~3개 + 가끔 수식어 단어)의 연속. 어근·접사 사용 빈도는 순위^-1 (Zipf).
- 모든 인벤토리와 표기가 **같은 골격**을 쓰고 형태만 바꾼다. 인벤토리마다 어휘(형태 배정)를 5번 새로 뽑아 합산했다.
- 어휘 크기: 어근 59개, 접사 34개 (세 인벤토리 공통, 가장 작은 풀에 맞춤).
- 경계 규칙: 공백은 뒤 형태소에 속한다. 공백이 따로 토큰이 되면 정밀도가 떨어진다.
- mistral_sp 의 "앞 공백 형태"는 `kat` 을 넣어 잰다 (SentencePiece 가 스스로 `▁` 를 붙이므로 `▁kat` 과 같다).

token-picked 어근은 엄격한 필터(zipf < 3)에서 59개뿐이다. 문서의 목표 어근 수(500~1,000개)에 크게 못 미친다.

## 7. 한계

- 토큰 경계가 형태소와 맞는지만 쟀다. 어긋남이 LLM 의 읽기·쓰기 정확도를 실제로 떨어뜨리는지는 이 실험으로 알 수 없다 (`pilot_segmentation.py` 같은 모델 실험이 필요하다).
- 현행 Claude 토크나이저는 공개되지 않아 잴 수 없다. claude_legacy 는 Claude 2 시절 토크나이저로 대용 지표일 뿐이다.
- token-picked + W2 가 5개 토크나이저에서 통과한 것은 선정 기준(앞 공백 형태 1토큰)과 거의 같은 조건이라 예상된 결과다. 이 실험이 새로 보여 주는 것은 (1) 문맥 안에서도 그 성질이 유지된다는 점, (2) 선정 때 자주 빠진 토크나이저(claude_legacy, mistral_sp)가 그대로 약점으로 남는다는 점이다.
- 어휘가 작다 (어근 59개, 접사 34개, 가장 작은 풀에 맞춤). 추첨 간 범위를 2절 표에 적었다.
- 접사 단어 필터는 zipf < 4.5 로 완화했다. W2 에서는 접사가 단독 토큰으로 보이므로 다른 언어의 짧은 단어처럼 보일 수 있다.
- token-picked 풀에는 vec, req, xor 처럼 영어 약어나 코드 조각으로 읽힐 수 있는 형태가 섞여 있다 (목록은 json 의 `token_picked_roots`). 단어 필터(wordfreq)가 이런 조각을 거르지 못하므로 사람 판독 저항성(G2)은 따로 따져야 한다.
- mistral_sp 의 붙여 쓴 형태 단독 토큰화는 toklib 으로 잴 수 없어 bare-picked 선정과 단독 측정에서 뺐다. 메시지 전체 측정에는 포함했다.

# 01. 언어 구조: 계층별 고려사항

언어를 아래 계층으로 나누고 아래층부터 하나씩 확정한다. 아래층의 결정이 위층의 선택지를 제한하기 때문이다.

```
L6  난독화 계층 (선택)   키 기반 어휘 치환 등
L5  담화·화용            지시 대상, 확신도, 출처, 화행
L4  통사론               단어 → 문장
L3  어휘·의미 체계       개념을 어근에 배정하는 방식
L2  형태론               형태소 → 단어
L1  형태소 모양          글자 → 형태소, 경계 찾기
L0  문자 집합            어떤 글자를 쓰는가
```

각 절은 선택지 → 판단 → 권장안 → 열린 질문 순서로 쓴다.
권장안은 모두 **제안** 상태이며, 확정하면 [README](../README.md)의 진행 현황표에 기록한다.
아래 예시의 어근과 접사 의미는 구조를 설명하려고 임의로 붙인 것이다.

---

## L0. 문자 집합

**선택지**

- (a) 소문자 26자
- (b) 대소문자 52자
- (c) 소문자 + 공백·구두점

**판단**

- 대소문자를 구분하면 글자당 정보량은 늘지만, 대소문자가 섞인 문자열은 토큰이 심하게 쪼개진다(G4 손해). 사람에게 주는 혼란에 비해 토큰 비용이 크다.
- 공백은 토큰 경계를 깔끔하게 만들어 AI에 유리하지만(G1, G4), 사람에게 단어 경계를 그대로 보여 준다(G2 손해).
- 숫자와 기호가 없으므로 숫자와 외래 문자열(고유명사, 코드, URL)을 글자만으로 적는 방법이 필요하다(L3에서 다룬다).

**권장안**: 소문자 a–z 26자만 쓴다. 공백을 쓸지는 **실험 변수**로 남겨 2단계 토큰화 실험에서 정한다.

L1에서 쓸 글자 분류:

- 모음 V = {a, e, i, o, u} (5자)
- 자음 C = 나머지 21자 (y 포함)

**열린 질문**: y를 모음으로 볼 것인가? 토큰화가 나쁜 글자(q, x 등)를 뺄 것인가?

## L1. 형태소 모양과 경계 찾기

공백이 없다면 "어디서 끊는가"를 글자 자체로 알 수 있어야 한다(자기 분절성, self-segmenting).

**선택지**

| 방식 | 설명 | 문제 |
|---|---|---|
| (a) 고정 길이 | 모든 형태소가 3글자 | 경계를 찾으려면 글자를 세야 한다 (LLM 약점) |
| (b) 모양 기반 | 자음·모음 배열이 형태소 종류와 경계를 알려 준다 (Lojban이 단어 모양 CVCCV 등으로 단어 종류를 구분하는 방식) | 모양 규칙이 표현 가능한 개수를 제한한다 |
| (c) 접두 부호 | 어떤 형태소도 다른 형태소의 앞부분이 되지 않게 배정한다 | 사전 없이는 끊을 수 없다 |
| (d) 길이 표시 글자 | 첫 글자가 형태소 길이를 알린다 | 글자를 세야 한다 (LLM 약점) |

**권장안 (스케치)**: 모양 기반, 형태소 두 종류

| 종류 | 모양 | 최대 개수 | 역할 |
|---|---|---|---|
| 어근 | CVC | 21 × 5 × 21 = 2,205 | 의미 (사물, 행위, 성질) |
| 접사 | VC | 5 × 21 = 105 | 문법 (격, 시제, 확신도 등) |

분절 규칙은 하나다. **다음 글자가 자음이면 어근(3글자), 모음이면 접사(2글자)를 읽는다.**
한 글자만 미리 보면 되므로 결정적이고, 글자를 셀 필요가 없다.

```
katenmirob  →  kat | en | mir | ob
               어근  접사  어근  접사
```

- 장점: 발음할 수 있는 음절 위주라 토크나이저 친화적일 가능성이 높고, 공백 없이도 파싱된다.
- 위험: 토크나이저가 `katenmirob`를 `k|aten|mir|ob`처럼 형태소 경계와 어긋나게 자를 수 있다. **2단계 실험의 핵심 질문**이다.
- 2,205개를 모두 쓸 필요는 없다. 영어 단어나 로마자로 적은 한국어 단어와 겹치는 것(cat, dog, man, bap 등)은 뺀다(G2).
  토큰화가 나쁜 자음을 빼면 개수가 줄어든다(예: 자음 16개 → 16 × 5 × 16 = 1,280개).

**열린 질문**: 모음 5개로 충분한가? 어근 개수의 상한은?

## L2. 형태론 (단어를 만드는 방식)

| 유형 | 예시 언어 | 특징 | AI 해독 (G1) | 사람 저항 (G2) |
|---|---|---|---|---|
| 고립어 | 중국어, 베트남어 | 단어 하나 = 형태소 하나, 어순으로 문법 표시 | 좋음 | 낮음 |
| 교착어 | 한국어, 터키어, 핀란드어 | 어근 + 접사 사슬, 접사 하나 = 의미 하나 | **매우 좋음** | 중간 |
| 굴절어 | 라틴어, 러시아어 | 접사 하나에 여러 의미가 융합, 불규칙이 많음 | 나쁨 | 높음 |
| 포합어 | 이누이트어, Ithkuil | 문장 전체가 한 단어 | 중간 | 매우 높음 |
| 어근-패턴 | 아랍어 (k-t-b → kataba "썼다", kitāb "책") | 자음 = 의미, 사이의 모음 = 문법 | **나쁨** (의미가 떨어진 글자에 흩어져 토큰과 어긋난다) | 높음 |

**권장안**: **교착어**. 접사 하나에 의미 하나, 예외 없음.
규칙이 조합적이어서 in-context learning에 가장 유리하고(G1) 파서를 만들기 쉽다(G3).
사람 저항성은 형태론의 복잡함이 아니라 어휘(L3)와 정보 밀도에서 확보한다.

**단어 경계**: 어근이 나오면 새 단어가 시작된다. 합성어(어근 + 어근)는 연결 접사로 명시한다.

```
kat | ol | mir | ob   →   [kat-ol-mir]-ob     (ol = 합성 연결 접사라고 가정)
```

**열린 질문**: 접사 순서 규칙 (예: 파생 → 수 → 격 → 확신도)

## L3. 어휘·의미 체계

| 방식 | 설명 | G1 | G2 | 비고 |
|---|---|---|---|---|
| 임의 배정 (a priori) | 개념마다 무작위 어근 | 사전 전체가 필요 | **매우 높음** | 사전 크기 = 사양 크기 |
| 분류학적 (Wilkins 1668, Ro) | 글자마다 범주를 좁힌다 (첫 글자 = 대분류 …) | 처음 보는 단어도 추측 가능 | 낮음 (체계를 배우면 다 읽힌다) | 분류가 틀리면 고치기 어렵다 |
| 의미 원소 (NSM, Toki Pona) | 수십~백여 개 기본 개념을 조합 | 사전이 매우 작다 | 중간 | 표현이 길고 모호해진다 (G4 손해) |
| 임베딩 좌표 | 개념 = AI 임베딩 공간의 양자화 좌표 | **불가** | - | 모델마다 공간이 다르고, LLM은 텍스트로 자기 임베딩을 볼 수 없다 |
| 혼합 | 핵심 어근(무작위 배정) + 조합 규칙 + 분야별 어근 | 좋음 | 높음 | |

임베딩 좌표는 "AI만 이해하는 언어"라는 말에 가장 잘 어울려 보이지만 실제로는 동작하지 않는다.

**권장안**: **혼합 방식**

- 핵심 어근 500~1,000개를 고빈도 개념(의미 원소 목록, 고빈도 어휘 목록 참고)에 무작위로 배정한다.
- 파생 접사로 체계적으로 확장한다 (예: 행위 → 행위자, 성질 → 반대 성질).
- 사전 규모 추정: 어근 1,000개 × 항목당 약 8토큰 ≈ 8천 토큰. 컨텍스트에는 가볍게 들어가지만 사람에게는 수개월치 암기량이다.
  **이 차이가 이 언어의 핵심 비대칭이다.**

**필수 탈출구**

- 숫자: 숫자 0–9마다 고정 음절을 둔다(10진법). LLM은 글자 단위 산술에 약하므로 진법 변환 같은 영리한 방식보다 단순 대응이 낫다.
- 외래 문자열(고유명사, 코드, URL): 인용 시작·끝 표지 사이에 원문 철자를 그대로 둔다. a–z 밖의 글자를 어떻게 적을지는 미정이다.

**열린 질문**: 핵심 개념 목록을 어디서 가져올 것인가? 의미가 가까운 개념끼리 비슷한 어근을 줄 것인가(학습은 쉬워지고 저항성은 낮아진다)?

## L4. 통사론 (문장 구조)

| 방식 | 설명 | 장점 | 단점 |
|---|---|---|---|
| 고정 어순 | 위치로 역할 결정 (SOV, SVO) | 단순 | 생략과 도치가 어렵다 |
| 격 표시 + 자유 어순 | 한국어 조사처럼 역할을 접사로 표시 | 순서를 섞어도 의미가 유지되어 사람이 헷갈린다 | 같은 뜻의 문장이 여러 개 (정규형이 없다) |
| 전위 표기 (술어가 항 개수를 정함) | `f x y`처럼 술어가 항 수를 정해 괄호가 필요 없다 | 완전히 비모호, 코드와 닮음 | 사전 없이 구조를 알 수 없고, 한 단어 오류가 전체를 무너뜨린다 |
| 술어 먼저 + 격 표시 + 절 경계 표지 | 술어 → 역할이 붙은 항들, 내포절은 열기·닫기 접사 | 비모호, 각 항이 스스로 역할을 밝힌다 | 접사 수가 늘어난다 |

**권장안**: **술어 먼저 + 격 표시 + 절 경계 표지**

- 술어를 먼저 두는 이유: LLM이 대량으로 학습한 함수 호출 `give(giver, gift, recipient)`와 같은 모양이고, 생성할 때도 관계를 먼저 정한 뒤 항을 채우게 된다.
- 항마다 역할(행위자, 대상, 수혜자, 도구, 장소 …)을 접사로 붙여 사전 없이도 구조를 파싱할 수 있게 한다.
- 정규 순서(canonical order)를 정해 같은 의미가 같은 문자열이 되게 한다(G3, 자동 평가에 유리). 자유 어순은 L6 난독화 옵션으로 남긴다.

```
의미: 사용자가 파일을 나에게 보냈다 (확실함, 직접 관찰)
구조: [보내다-과거-확실-관찰] [사용자-행위자] [파일-대상] [나-수혜자]
```

**열린 질문**: 의미역(역할) 목록의 크기, 수식어(형용사·부사)의 위치, 관계절 표시 방법

## L5. 담화·화용: AI 특화 문법 범주

자연어에는 없거나 선택 사항인 정보 중 AI끼리 소통할 때 유용한 것을 **필수 문법 범주**로 만들 수 있다.
이 언어가 단순한 암호와 달라지는 지점이다.

| 범주 | 값 예시 | 자연어 대응 |
|---|---|---|
| 확신도 | 확실 / 높음 / 낮음 / 모름 | 영어 "probably" (선택 사항) |
| 증거성 (출처) | 직접 관찰 / 추론 / 사용자 진술 / 도구 결과 / 사전 지식 | 한국어 "-더라", "-대", 터키어·케추아어의 증거성 |
| 화행 | 단언 / 질문 / 요청 / 명령 / 제안 | 한국어 종결어미 (-다, -니, -자, -라) |
| 지시 대상 | 번호 붙은 변수 (①, ②)를 대명사 대신 사용 | 없음 (자연어 대명사는 모호하다) |
| 양화 범위 | 모든 / 어떤 / 없음 + 범위 명시 | 논리식의 ∀, ∃ |

**권장안**: 확신도, 증거성, 화행은 문장마다 반드시 표시한다. 지시 대상은 번호 변수로 쓴다.

**열린 질문**: 필수 범주가 많을수록 짧은 문장이 길어진다(G4 손해). 기본값은 생략하는 규칙을 둘 것인가?

## L6. 난독화 계층 (선택)

목적이 "사람에게 숨기기"라면, 통신하는 쪽끼리 키(시드)를 공유해 어근 배정표를 섞을 수 있다.
키가 없는 사람(그리고 다른 AI)은 읽을 수 없다.
다만 이것은 형태소 단위의 치환 암호여서 문장이 충분히 쌓이면 빈도 분석으로 깨질 수 있다. 보안이 필요하면 표준 암호화를 쓴다.

**권장안**: 보류. 프로젝트 목적이 정해진 뒤 결정한다.
